1. 系統概觀

AutoResearchClaw（以下簡稱 ARC）是一個 23 階段自主科研管線（autonomous research pipeline），輸入一個研究題目即可輸出 期刊/會議級別的論文草稿、實驗代碼、圖表與經過驗證的 references.bib。 ARC 將整個流程切分為 8 個 Phase；本文件聚焦於 Phase B（文獻發現） 與 Phase H（最終驗證）之間關於檢索（Search）與引用（Citation）的所有技術細節。

PhaseStage（編號）角色
B3 SEARCH_STRATEGYLLM 規劃多策略查詢計畫
B4 LITERATURE_COLLECT呼叫 OpenAlex / Semantic Scholar / arXiv 收集論文
B5 LITERATURE_SCREEN（Gate）關鍵字預過濾 + LLM 篩選
B6 KNOWLEDGE_EXTRACT抽取結構化證據卡片
G17 PAPER_DRAFT注入 cite_key 與引用規則，產出論文
G/H22 EXPORT_PUBLISH解析正文引用、回填 cite_key、修剪 BibTeX
H23 CITATION_VERIFY四層引用真實性驗證
本研究的核心問題：ARC 如何在 LLM 容易「幻覺」引用的場景下，從查詢規劃一路守住引用真實性？ 從程式碼觀察，答案是「四道防線疊加」：詞彙預過濾 → LLM 篩選 → 預先 verify（草稿前）→ 最終 verify（出口前）。

2.2 關鍵資料模型

Paper（literature/models.py:32–51）為 frozen dataclass， 欄位包含：paper_id, title, authors, year, abstract, venue, citation_count, doi, arxiv_id, url, source, _bibtex_override。 cite_key 規則為 lastname + year + keyword（取首位作者姓氏 ASCII 折疊 + 年份 + 標題首個非停用詞名詞）。 

# 範例
Paper(title="Attention Is All You Need", authors=[Author("Vaswani")], year=2017, ...)
.cite_key  # → "vaswani2017attention"

to_bibtex()（models.py:78–152）負責產生 BibTeX，會自動偵測 arXiv 分類碼 （如 cs.CY）與真正期刊／會議名稱差異，並選擇 @inproceedings / @article 條目型別。

3. Stage 3 — Search Strategy：LLM 規劃查詢計畫

3.1 Prompt 設計

Prompt 位於 prompts.default.yaml:382–399，採用 json_mode: true。 系統訊息要求「瞄準 30–60 篇參考文獻的完整覆蓋」，使用者訊息要求 LLM 產出： 

{
  "search_plan_yaml": "<valid YAML>",
  "sources": [{ "id", "name", "type", "url", "status", "query", "verified_at" }]
}

YAML 內須包含至少 3 個策略，每個策略 3–5 個 3–6 個字的查詢， 總計至少 8 條查詢，並涵蓋：核心題目、相關方法、Benchmark/Dataset、理論基礎、應用場景。

3.2 容錯：規則式查詢擴展

若 LLM 失敗或產出空計畫，stage_impls/_literature.py:41–78 提供 fallback： 取題目前 5 字、後 5 字、以及 topic + survey / benchmark / comparison 等後綴， 以 set 去重後送入下游。這保證 Stage 3 永遠不會「卡死」管線。

4. Stage 4 — Literature Collection：多源檢索與容錯

4.1 三來源呼叫順序（依 rate-limit 友善度排序）

順序來源速率限制快取 TTL容錯機制
1OpenAlex10,000 req/day（含 polite email），200 ms 間隔3 天—
2Semantic Scholar1 req/s（程式中保守設 1.5 s）3 天三態斷路器：3 連續 429 → OPEN（120 s），HALF_OPEN 探測，最長 600 s
3arXivarxiv 套件內建退避24 小時斷路器 + 180 s 冷卻

原始檔：literature/search.py:104–200

4.2 斷路器三態（Three-State Circuit Breaker）

位於 semantic_scholar.py:43–140。設計可在 API 不穩定時優雅降級：

  • CLOSED 正常呼叫
  • OPEN 跳過呼叫，避免雪崩，冷卻時間採指數退避（120 s → 600 s）
  • HALF_OPEN 冷卻結束後送一筆探測請求，成功則 CLOSE，失敗則加倍冷卻時間並回到 OPEN

4.3 去重策略

多源合併後採三層去重（search.py:270–348）： DOI → arXiv ID → 正規化標題完全比對。 其中第三層是把標題小寫化、去標點後做嚴格等值比對（_normalise_title，search.py:270–276）， 並非模糊 Jaccard。模糊 Jaccard 相似度僅用於 citation verify 的標題比對，與此處去重無關。

4.4 快取設計

literature/cache.py:32–142。Key 為 SHA256(query.lower() | source | limit)[:16]， per-source TTL：arXiv 24 h、Semantic Scholar/OpenAlex 3 天、Citation verify 365 天（接近永久）。 快取目錄：.researchclaw_cache/literature/，序列化格式為 JSON 文字檔。

5. Stage 5/6 — Screening 與 Knowledge Extract

5.1 兩段式篩選

  1. P1-1 關鍵字預過濾（_literature.py:640–663）： 從題目抽取關鍵字，標題＋摘要至少命中 1 個關鍵字（原為 ≥ 2，已放寬以避免誤刪）。 若預過濾全數刪除，安全閥退回原始集合。
  2. P1-2 LLM 篩選（prompt literature_screen，prompts.yaml:171–191）： LLM 對每篇打分 relevance_score 與 quality_score， 系統訊息明確指示「aggressive reject off-topic papers」。 篩選結果保留所有原始欄位（paper_id、doi、arxiv_id、cite_key 等）。

5.2 Stage 6 Knowledge Extraction

Prompt knowledge_extract（prompts.yaml:145–156）以 JSON 模式回傳結構化的證據卡片： {card_id, title, cite_key, problem, method, data, metrics, findings, limitations, citation}。 關鍵約束：「If the input contains cite_key fields, preserve them exactly」── 確保 cite_key 一路傳遞不變。

6. Stage 23 — Citation Verify：四層驗證引擎

核心檔：literature/verify.py（957 行）。零外部依賴，僅用 stdlib urllib。

6.1 分類結果

狀態含義標題相似度
VERIFIEDAPI 確認存在且標題吻合≥ 0.80
SUSPICIOUS找到但 metadata 偏離0.50–0.80
HALLUCINATED任何 API 都找不到 / 相似度過低< 0.50
SKIPPED無標題、所有 API 都無法連線、或超時—

6.2 四層驗證順序

Layer 1：arXiv ID 查詢

verify.py:183–265。對 https://export.arxiv.org/api/query?id_list={arxiv_id} 做 GET， 解析 Atom XML。若條目本身寫了 arxiv_id 則優先走此路。Timeout 20 s。 標題比對採詞彙 Jaccard（verify.py:158–172）。

Layer 2：DOI 解析（CrossRef → DataCite Fallback）

verify.py:358–442。先打 https://api.crossref.org/works/{doi}， 若 404 且 DOI 以 10.48550/ 開頭（arXiv 自家 DOI），改打 DataCite https://api.datacite.org/dois/{doi}。Timeout CrossRef 20 s、DataCite 15 s。

Layer 3a：OpenAlex 標題搜尋（verify_by_openalex）

verify.py:454–527。由於 OpenAlex 每天可打 10,000 次（遠寬於 arXiv 1 req/3 s）， 被提升為標題搜尋的「主力」。回傳分數最高的標題；若無近似匹配標記 HALLUCINATED。

Layer 3b：統一標題搜尋（verify_by_title_search，最後手段）

verify.py:577–655。前述路徑都失敗時呼叫 search_papers()，limit=5。 注意：此函式雖然以「title_search」命名，實際上會同時查詢 Semantic Scholar 與 arXiv（透過統一檢索器），並非僅打 S2。 這層命中率最低，作為最後一道網。

6.3 主驗證流程

# verify.py:663-859 簡化版
def verify_citations(bib_text, *, s2_api_key="", inter_verify_delay=1.5):
    entries = parse_bibtex_entries(bib_text)        # L122-150
    for entry in entries:
        if cache_hit(entry.title): continue          # 365 天快取
        # 嚴格的呼叫順序（每層之間有 sleep）
        result = (
            verify_by_doi(entry.doi, entry.title, delay=0.3)
            or verify_by_openalex(entry.title, delay=0.2)
            or verify_by_arxiv_id(entry.arxiv_id, entry.title, delay=1.5)
            or verify_by_title_search(entry.title)   # 同時打 S2 + arXiv
        )
        save_cache(entry.title, result)
        if time_elapsed() > 300: break               # 全局 5 分鐘 timeout（BUG-22）
    return VerificationReport(...)

6.4 完整性分數

integrity_score = verified / (total − skipped)，0.0–1.0。 此分數寫入 verification_report.json 作為論文最終 deliverable 之一。

7. 反幻覺：VerifiedRegistry 與 BibTeX 修剪

7.1 寫作前的預驗證（P3）

_paper_writing.py:1910–1932。Stage 17 在送 LLM 撰寫前先跑一次 verify_citations （inter_verify_delay 縮為 0.5 s），並呼叫 filter_verified_bibtex(..., include_suspicious=True) 把 HALLUCINATED 條目從 references.bib 中剔除，避免 LLM 從假引用中取材。

7.2 引用指令注入

AVAILABLE REFERENCES (use [cite_key] to cite in the text):
- [smith2024transformer] → TITLE: "Transformer Architecture..."

CRITICAL CITATION RULES:
- In the body text, cite using [cite_key] format
- Do NOT invent references
- SEMANTIC MATCHING: verify title matches concept
- Cite 25-40 unique references total
- Related Work alone should cite 15+ references

來源：_paper_writing.py:1959–1984

7.3 Stage 22 — Author-Year 回填與 BibTeX 修剪

Stage 19 的 LLM 修訂常會把 [smith2024transformer] 改寫為 (Smith et al., 2024)。 _review_publish.py:1742–1806 建立 author-year ↔ cite_key 映射並反向回填。

之後 Stage 22 抽取所有正文引用鍵（單鍵 [xxx]、複合鍵 [xxx, yyy] 或 [xxx; yyy]）， 與 references.bib 的鍵集合做差集：

  • 有條目但正文沒引用 → 從 .bib 修剪（README 稱 "auto-pruned to match inline citations"）
  • 正文引用但 .bib 沒條目（且總缺失 ≤ 30）→ 呼叫 _resolve_missing_citations() 反查 API 補上
  • 仍無法解析者 → 直接從正文中刪除該引用，避免 LaTeX 編譯破窗

7.4 VerifiedRegistry：數字防偽（與引用驗證互補）

pipeline/verified_registry.py:38–450。此模組與 citation verify 平行， 但作用對象是「論文中的所有數字」。從 experiment_summary.json 抽取所有 verified 數值 （per-seed、condition aggregates、best_run metrics），並登錄其四捨五入變體（1–4 位小數）與百分比換算。

論文驗證器（paper_verifier.py:143–200+）以正則抽 LaTeX 數字， 在「嚴格段落」（Results、Experiments、Ablations）對未登錄數字直接 REJECT； 在「寬鬆段落」（Introduction、Discussion）僅給 WARNING。

8. ★ 完整生命週期：Search → Citation 端到端

本章為任務核心。將以「一個輸入主題 "adaptive learning rate schedules for transformers" 」為例，逐步追蹤資料流。

Step 1 — 主題輸入與分解（Stage 1–2）

CLI researchclaw run --topic "adaptive ..." 觸發 Runner，將主題傳給 Stage 1（TOPIC_INIT，產 SMART goal） 與 Stage 2（PROBLEM_DECOMPOSE，產 problem tree JSON）。 兩者的輸出將是 Stage 3 的 prompt 變數 {topic} 與 {problem_tree}。

Step 2 — 查詢規劃（Stage 3 SEARCH_STRATEGY）

Prompt（prompts.yaml:382）以 JSON mode 呼叫 LLM，回傳 search_plan_yaml + sources。 若 LLM 失敗，_literature.py:41–78 規則式擴展備援。 產出寫入 artifacts/rc-*/stage-03/search_plan.yaml。 

search_strategies:
  - name: core
    queries: ["adaptive learning rate", "lr schedule transformer", ...]
    sources: [openalex, semantic_scholar, arxiv]
  - name: benchmark
    queries: ["GLUE benchmark optimizer", ...]
  - name: theory
    queries: ["convergence analysis adaptive optimization", ...]

Step 3 — 多源檢索（Stage 4 LITERATURE_COLLECT）

search.py:104–200 的 search_papers() 依序：

  1. 查 cache（key = SHA256(query|source|limit)[:16]，3 天 TTL）；命中即返回。
  2. OpenAlex：每筆 200 ms 間隔；轉成 Paper 物件。
  3. Semantic Scholar：先檢查斷路器狀態；若 OPEN 則跳過。每筆 1.5 s 間隔。
  4. arXiv：用 arxiv 套件搜尋；斷路器在外層守護。
  5. 合併後去重（DOI → arxiv_id → 正規化標題完全比對）。
  6. 對每篇 Paper 呼叫 to_bibtex() 生成條目，寫入 stage-04/references.bib。
  7. 同時寫 stage-04/candidates.jsonl。
觀察：BibTeX 條目在「Stage 4 收論文當下」就生成，cite_key 也在此時固化。後續所有階段都共享同一份鍵命名空間。

Step 4 — 雙重篩選（Stage 5，Gate）

先跑詞彙預過濾（標題＋摘要至少 1 個 topic keyword），再以 LLM 篩選器 （prompt literature_screen）打 relevance / quality score。 Gate 5 預設需人類點頭；--auto-approve 模式跳過。 輸出 stage-05/shortlist.jsonl。

Step 5 — 知識抽取（Stage 6 KNOWLEDGE_EXTRACT）

LLM 以 JSON 模式把每篇 shortlist 變成 evidence card： {card_id, cite_key, problem, method, data, metrics, findings, limitations, citation}。 Prompt 明確要求「保持 cite_key 不變」。輸出 stage-06/evidence_cards.jsonl。

Step 6 — 寫作前的「預驗證」（Stage 17 PAPER_DRAFT 前置）

_paper_writing.py:1910–1932。在請 LLM 寫初稿前先跑一次 verify_citations， 用 filter_verified_bibtex(include_suspicious=True) 從 .bib 移除 HALLUCINATED 條目。 這是第一道引用守門。

Step 7 — LLM 撰寫並插入 [cite_key]（Stage 17）

Prompt 明列「AVAILABLE REFERENCES」清單與 CRITICAL CITATION RULES，要求 LLM 只能使用清單中的 cite_key、 禁止發明、Related Work 至少 15 引用、全篇 25–40 引用。 LLM 輸出 markdown：Recent work [smith2024transformer] has shown ...

Step 8 — Peer Review 與 Revision（Stage 18–19）

多代理同儕審查 + Methodology-Evidence 一致性檢查。 Revision 可能將 [xxx2024yyy] 改寫為 (XXX et al., 2024)。

Step 9 — Export 階段的引用一致化（Stage 22）

_review_publish.py:1727–1919 三步驟：

  1. Author-year 回填：建構 (author, year) → cite_key 映射，把自然語言引用反向轉回方括號形式。
  2. 引用鍵抽取：用 regex [a-zA-Z]+\d{4}[a-zA-Z0-9_-]* 抽出所有 cite_key（含複合 [a,b;c] 形式）。
  3. BibTeX 修剪 + 缺失補回：未引用之 .bib 條目被移除；正文有但 .bib 無者，若總缺失 ≤ 30 則呼叫 API 補回，否則從正文刪除。

Step 10 — 最終 Citation Verify（Stage 23）

verify.py:663–859。對最終 references.bib 跑完整四層驗證， 輸出 verification_report.json： 

{
  "summary": {
    "total": 38, "verified": 35, "suspicious": 2,
    "hallucinated": 1, "skipped": 0, "integrity_score": 0.921
  },
  "results": [
    {"cite_key":"vaswani2017attention","status":"verified","method":"arxiv_id","confidence":1.0,...},
    {"cite_key":"fake2024made_up","status":"hallucinated","method":"title_search","details":"no match"}
  ]
}

這是第二道引用守門。整份報告會與 paper.tex、references.bib 一起放入 deliverables/。

9. 技術優缺點分析

優點

  • 四層驗證 + 雙時點驗證（草稿前 + 出口前）有效堵住 LLM 引用幻覺
  • 三態斷路器面對 S2/arXiv 429 與不穩 API 仍能優雅降級
  • 零外部依賴的 verify.py（純 stdlib urllib）部署友善
  • cite_key 在 Stage 4 一次定錨，所有下游階段共享；避免 ID 漂移
  • 365 天的 verify 快取顯著節省重跑成本（同一論文驗證一次即可）
  • Author-year ↔ cite_key 自動雙向轉換，吸收 LLM 風格漂移
  • BibTeX 自動修剪確保 .bib 與正文嚴格一致，無 dangling reference
  • VerifiedRegistry 與引用驗證形成「引用真偽 + 數字真偽」的雙軌反幻覺

缺點與風險

  • S2 / arXiv 是公開速率受限服務；大規模驗證會被全域 5 分鐘 timeout 截斷
  • 標題相似度為 Jaccard 詞彙，對 typo、副標題切割較弱
  • OpenAlex 雖然作主力，但其 metadata 在新領域論文上覆蓋不全
  • cite_key 生成依賴 ASCII 折疊，CJK 作者姓氏可能塌縮成相同鍵
  • LLM 篩選若 hallucinate relevance_score，預過濾門檻偏低（1 個關鍵字）難以攔截
  • SUSPICIOUS 預設仍會保留進入論文，存在「半幻覺」漏網風險
  • 整體流程倚重 LLM JSON mode 穩定性；模型若回傳非 JSON 將進入 fallback 路徑
  • 沒有針對 retracted papers / preprint vs published 的特殊處理

10. 附錄：交付給其他 Coding Agent 的覆現 Prompt

以下 prompt 設計為可直接貼給另一個 coding agent（Claude Code / Codex / Cursor / Aider 等）， 令其在 ~1500 行 Python 內覆現 ARC 的 Search & Citation 邏輯（不含 LLM 寫作部分）。

使用方式：複製下方 <pre> 區塊整體內容，貼到目標 agent 的對話起始。 Agent 完成後請手動驗證：（a）四層驗證可分別跑通；（b）斷路器在連續 429 後切換到 OPEN； （c）BibTeX 自動修剪能正確移除無引用條目。 
# ROLE
You are a senior Python engineer. Your task is to reproduce the
**search → literature collection → citation verification** subsystem of
AutoResearchClaw (ARC) as a standalone, runnable library. No LLM is required
for the verification path — only the literature_screen and search_strategy
stages call an LLM (provide a mock/dry-run mode).

# DELIVERABLES
A pip-installable package `litverify/` with the following modules. All HTTP
must use only Python stdlib `urllib` (no `requests`, no `httpx`). Total target
~1500 LOC.

litverify/
├── models.py          # Paper, Author, cite_key, to_bibtex
├── cache.py           # SHA256-keyed, per-source TTL, JSON-on-disk cache

# DATA MODEL — models.py
@dataclass(frozen=True)
class Author: name: str
@dataclass(frozen=True)
class Paper:
    paper_id: str; title: str; authors: tuple[Author, ...]; year: int|None
    abstract: str = ""; venue: str = ""; citation_count: int = 0
    doi: str = ""; arxiv_id: str = ""; url: str = ""
    source: str = ""   # "openalex"|"semantic_scholar"|"arxiv"
    _bibtex_override: dict|None = None

    @property
    def cite_key(self) -> str:
        # lastname (ASCII-folded, lowercased) + year + first meaningful
        # word from title (>3 chars, not stopword).
        # Stopwords: {"the","a","an","of","and","for","with","on","in","to",
        #             "from","via","by","using","through","towards"}
        # Example: Paper("Attention Is All You Need", [Author("Vaswani")], 2017)
        #          -> "vaswani2017attention"

    def to_bibtex(self) -> str:
        # Heuristics:
        #  - If venue looks like arXiv category (regex: r"^[a-z]{2}\.[A-Z]{2}$"
        #    e.g. "cs.LG") OR source == "arxiv" -> @article with journal={arXiv preprint arXiv:{id}}
        #  - If venue in conference list (NeurIPS, ICML, ICLR, ACL, EMNLP,
        #    CVPR, ICCV, ECCV, AAAI, IJCAI, KDD, WWW, SIGIR, ...) -> @inproceedings
        #  - Else -> @article
        #  - Include doi field if present, eprint+archivePrefix if arxiv_id present

# CIRCUIT BREAKER — circuit_breaker.py
class CircuitBreaker:
    """Three-state breaker.
       CLOSED -> OPEN after `failure_threshold` consecutive failures.
       OPEN -> HALF_OPEN after `cooldown` seconds (start 120s, double on
              each re-open up to `max_cooldown` 600s).
       HALF_OPEN: a single probe request; on success -> CLOSED & reset cooldown;
                  on failure -> OPEN & cooldown *= 2."""
    def __init__(self, failure_threshold=3, initial_cooldown=120,
                 max_cooldown=600): ...
    def call(self, fn, *args, **kw): ...     # raises CircuitOpen if OPEN
    def record_success(self): ...
    def record_failure(self): ...

@dataclass
class VerificationReport:
    total: int = 0; verified: int = 0; suspicious: int = 0
    hallucinated: int = 0; skipped: int = 0
    results: list[CitationResult] = field(default_factory=list)
    @property
    def integrity_score(self) -> float:
        verifiable = self.total - self.skipped
        return 1.0 if verifiable <= 0 else round(self.verified/verifiable, 3)

# CRITICAL INVARIANTS (do not break)
1. cite_key MUST be deterministic given (first author surname, year, title).
2. Verification call order MUST be: doi -> openalex -> arxiv_id -> title_search.
   (OpenAlex before arXiv because rate limit; S2 last because most aggressive.)
3. 365-day cache for verify results, keyed by sha256(normalized_title).
4. Stdlib only for HTTP. No `requests`. The arxiv pypi package is the ONLY
   exception.
5. Three-state breaker: OPEN -> HALF_OPEN MUST send exactly ONE probe before
   transitioning.
6. Global verify timeout = 300s; on timeout, mark remaining entries SKIPPED
   (not HALLUCINATED) and return partial report.
7. filter_verified_bibtex MUST preserve original entry order and formatting
   of kept entries (no re-rendering of unrelated fields).
8. Jaccard similarity MUST lowercase + remove punctuation + remove stopwords
   before tokenization.
